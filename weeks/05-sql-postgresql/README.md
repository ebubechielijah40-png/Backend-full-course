# Week 5 — SQL and PostgreSQL

## What students already know

A database-backed Django site using models and the admin (Week 4), but
no direct SQL knowledge yet — the ORM has been hiding it.

## What they need to learn this week

- What a relational database is, and PostgreSQL setup.
- `SELECT`, `WHERE`, `INSERT`, `UPDATE`, `DELETE`.
- Primary keys, foreign keys, and normalization at a beginner level.
- `JOIN`s across multiple tables.

## What they will build

A **Library Catalog** SQL project: schema design (books, authors,
borrowers or similar) plus a required set of queries against it, written
directly in SQL — deliberately outside Django.

## Concepts necessary to build it

None beyond general problem-solving; this week intentionally does not
depend on Django so students understand relational data on its own
terms before returning to the ORM in Week 6.

## What should NOT be taught yet

- The Django ORM (Week 6) — no Django code this week at all.
- Advanced normalization theory beyond first/second normal form basics.
- Database performance tuning or indexing strategy.

## What the three sessions accomplish

1. Relational databases and PostgreSQL setup.
2. Core statements: `SELECT`/`WHERE`/`INSERT`/`UPDATE`/`DELETE`.
3. `JOIN`s and multi-table queries.

## What the project accomplishes

Builds genuine SQL fluency that Week 6 will connect directly to Django,
so the ORM stops feeling like "magic."

## Practical skill at week's end

Can design a small relational schema and write correct multi-table SQL
queries against it, independent of any framework.
