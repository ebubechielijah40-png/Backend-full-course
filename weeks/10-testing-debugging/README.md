# Week 10 — Testing and Debugging

## What students already know

A complete, working Task Manager API (Week 9), built and manually
verified but not yet automatically tested.

## What they need to learn this week

- Django's test framework and `TestCase`.
- Testing views and API endpoints with DRF's test client.
- Reading tracebacks and isolating a bug with a minimal reproduction.

## What they will build

An automated **test suite for the Task Manager API**, plus debugging
work on deliberately broken versions of it provided by the instructor.

## Concepts necessary to build it

Week 9's finished project — this week tests and debugs that exact
application rather than building a new one.

## What should NOT be taught yet

- Security hardening and deployment (Week 11) — kept separate so testing
  gets full attention.
- Advanced tooling (coverage tools, mocking libraries, performance
  testing) — out of scope for this course.

## What the three sessions accomplish

1. Why and how to test; unit tests for models.
2. Testing views and API endpoints.
3. Systematic debugging on real, injected bugs.

## What the project accomplishes

Applies testing to a project students already understand deeply, and
turns debugging into a taught, systematic skill rather than trial and
error.

## Practical skill at week's end

Can write meaningful automated tests and debug an unfamiliar failure
systematically.
