# Week 11 — Security, Deployment, and Git/GitHub

## What students already know

A working, tested Task Manager API (Weeks 9–10).

## What they need to learn this week

- Common backend security mistakes and how to avoid them (secrets,
  `DEBUG=False`, `ALLOWED_HOSTS`, input validation review).
- Environment variables and production settings.
- Deploying to a live hosting environment with a production database.
- Git branching basics and a real GitHub workflow.
- Reading deployment logs to diagnose failures.

## What they will build

The **Task Manager API, hardened, deployed, and on GitHub** — the same
project from Weeks 9–10, shipped.

## Concepts necessary to build it

The finished, tested Week 10 project; Git usage that's been informal
since Week 1 is formalized here.

## What should NOT be taught yet

- Containerization (Docker) or CI/CD pipelines — out of scope for this
  course (see `COURSE_SPEC.md`).
- The capstone (Week 12) — this week deploys the known Task Manager
  project, not a new one.

## What the three sessions accomplish

1. Common backend security mistakes and how to avoid them.
2. Environment variables, production settings, and deployment.
3. Git/GitHub workflow, deploying, and verifying the live result.

## What the project accomplishes

Takes a project students have built, tested, and understand, and puts it
in front of the internet responsibly — closing the loop from "code on my
machine" to "a real, running service."

## Practical skill at week's end

Can take a working local backend and ship it to a live, reasonably
secure deployment.
