# Week 9 — Complete Backend Project

## What students already know

Models, ORM, REST API design, and authentication/permissions (Weeks
3–8), each individually demonstrated on the Library Catalog.

## What they need to learn this week

No new syntax. This week is integration: reading a written specification
and combining models, ORM, API, and auth into one coherent backend, with
reduced step-by-step guidance (see `TEACHING_GUIDE.md`).

## What they will build

A **Task Manager API** — a new application, built from a written spec,
reusing every skill from Weeks 3–8.

## Concepts necessary to build it

Everything from Weeks 3–8; nothing new is introduced.

## What should NOT be taught yet

- Testing (Week 10) — this week's success criterion is a working,
  manually-verified API, not an automated test suite.
- Deployment or security hardening (Week 11).

## What the three sessions accomplish

1. Planning from the written spec: identifying models and endpoints.
2. Building models, ORM layer, and API together.
3. Adding auth and finishing the feature set.

## What the project accomplishes

Proves students can combine prior skills on a new problem without being
walked through it step by step — the first real independence checkpoint.

## Practical skill at week's end

Can take a written spec and build a complete, authenticated CRUD backend
with moderate independence.
